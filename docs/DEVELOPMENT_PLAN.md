# Strata Manager 开发计划

更新：2026-10-13。当前交付仍为本机 Strata 工作台，只管理本应用安装或导入的本机安装，支持已有安装导入；Linux 多实例、远程节点和跨主机负载管理保留为后期路线。本轮资源适配、启动诊断、等待解释、能力说明、API 验证和性能对照见 [日常体验增量](DAILY_EXPERIENCE.md)。读取状态不会恢复已停止模型。

完整架构、用户流程、数据口径、实测调优依据及生产门槛见 [生产化改造方案](PRODUCTION_REDESIGN.md)。独立后台、本机流程、API 元数据统计、调优、自启动及更新已进入实现和验收，实际通过范围及缺项见 [验收记录](VERIFICATION.md)。以下明确标为旧原型的流程供迁移参考，不能替代新架构的真实运行和发布验收。

生产版导航收敛为总览、模型、聊天、调优、监控、设置；监控标签保留API/性能/请求/日志，设置容纳环境/更新/策略/关于。总览展示可用性、真实用量、速度与资源压力；缺失和采集断档不显示零。

生产版首次使用自动发现已有安装，或选择用途与模型后一键准备，再进入聊天/API接入。Python路径、端口与managed选择由后台维护。既有安装导入先只读识别，身份和空闲核验后迁移；原文件与模型保留。

## 新实施顺序

1. P0：Rust workspace、Supervisor与用户限定IPC、实体/旧数据迁移、自动检测/导入/启动加载。
2. P1：六主入口、系统窗口行为、共享工具栏/状态栏、一体安装任务、托盘和登录自启动。
3. P2：metadata-only观测、后台持续采集、SQLite历史及使用/性能/明细视图。
4. P3：场景基准、有限候选、A/B/A复验、质量门槛、原子应用/回滚与报告。
5. P4：三级更新、签名发布链、版本化回滚、安装/升级/睡眠唤醒/持续负载验证。

## 架构和目录

- `apps/desktop`：React、TypeScript、Vite 桌面前端及 Tauri 2 Rust 外壳，原生请求通过 IPC 交给独立后台。
- `apps/supervisor` 与 `crates/runtime-core`：独立后台及本机运行、安装、统计、调优逻辑；`crates/local-ipc` 负责用户限定通信，`crates/update-verifier` 在发布前验证实际更新包签名。
- 前端采用嵌套布局：应用布局负责共享且可收起的侧边栏，工作区布局负责共享 Header 和页面容器；聊天、监控、关于、运行配置及总览为独立模块。Header 通过 actions slots 保留 API Monitor 鉴权等页内操作，避免重复实现。
- `packages/core`：共享类型、Strata API/SSE 适配、监控归一化、模型目录和协议测试。
- pnpm workspace 管理前端依赖；Cargo 管理原生依赖；SQLite 持久化应用数据，系统凭据库保存 API Key。
- 浏览器预览只连接用户配置的真实 HTTP 服务，不提供虚构运行状态；原生安装、进程和日志能力在 Tauri 中执行。

## 当前原型阶段与验收

1. **仓库和运行基础**：创建 Git `main`、pnpm workspace、双语导航、主题、应用存储、服务档案。验收 typecheck、前端生产构建、原生编译。
2. **真实服务闭环**：健康/能力探测、启动停止、加载卸载、配置读写、日志；区分受管进程与外部连接、HTTP 在线与模型已加载。验收真实请求、错误与 409 忙碌行为。
3. **聊天与监控**：SSE、reasoning、取消、附件、MCP 工具事件、多会话持久化、Markdown 导出；真实 `/metrics`、请求查看器、硬件/吞吐图表。验收流分块、重启恢复、缺失指标不显示零。
4. **模型和环境**：官方目录、安装/下载任务、失败重试、路径导入、配置切换、运行环境检查、诊断导出；运行时版本记录、官方更新入口。Git 克隆失败重试保留半成品后重新获取，模型下载的缓存与续传由上游准备脚本管理，不能将 Git 重试称作字节断点续传。验收任务取消/失败、目录/参数校验和无关文件保护。
5. **交付验证**：协议及原生管理逻辑测试、真实浏览器中英文与交互验收、Tauri 构建；记录实际模型服务/物理 GPU 验收范围，提供使用说明。

## 当前原型生命周期与数据规则（待迁移）

- 默认关闭窗口进入托盘；明确退出时清理本应用启动的进程树，不停止仅连接的外部服务。
- 模型加载、卸载与 API 服务停止为独立操作；跨模型切换使用配置档案和受控重启。
- 不把 `/v1/models` 当成本地磁盘目录；不假定任意 GGUF 可被 Strata 执行。
- 配置保存前校验、备份；显示需要重启的参数；版本差异采用能力探测。
- 参数页提供下一请求生效的采样入口、官方 15 项运行设置、上下文/KV/线程启动设置、单字段默认值与重新读取；服务启动参数保持其他模型、MCP、安全和未知字段。
- 现有服务检测是只读操作；接管需核验端口、Python、完整启动参数、配置路径和进程创建时间，拒绝繁忙或身份不明的进程。接管先确认再重启；不在退出时清理仅检测或连接的外部进程。
- 安装目录仅在本应用 SQLite 记录和归属标记一致时重试，拒绝认领未知非空目录；任务输出脱敏并持久化到 SQLite，跨应用重启仍可读取。
- 模型及附件独立于应用安装包。语言切换不改模型内容、原始日志或 API 参数。
- 原始请求正文查看由用户按需启用，诊断包脱敏 API Key。

## 官方界面还原验收

- 固定参考版本 `fb58e0dbc8399662c0e47c76578c6e878b14f6cf`；记录上游源码、许可和每个页面的元素映射。
- 沿用官方组件外观；下拉、开关、分段选择和弹层使用自定义绘制控件，避免浏览器默认控件外观。文本输入、range/number 等保留 HTML 语义并使用完整官方样式。
- 英文、相同主题、相同工作区可用尺寸和相同协议数据下对照官方页面截图；官方视觉控件和内容元素保持，导航、聊天历史和配置位置按用户最后确认调整。逐项检查字号、间距、图标、图表、提示、空状态和弹层，明确区分官方样式复用与用户授权的结构调整。
- 检查中英文切换、深浅主题、键盘交互、SSE 及取消、附件、复制/导出、请求正文查看、共享采样和配置保存。
- 能力条件造成的隐藏元素依据上游 API 返回检查；硬件值、请求正文和模型内容不得为视觉验收虚构。
- 逐页元素清单见 `OFFICIAL_UI_PARITY.md`，实际验证范围和未覆盖项目见 `VERIFICATION.md`。

## 生产迁移约束

机房路线独立后移：先承接同机副本，再引入节点、部署实例和资源域。UI与后台生命周期分离，UI更新不关闭模型；运行时更新等待空闲且可能短暂停服。HTTP调用与推理run统计分开，默认不持久化正文。官方CLI只生成调优候选，需本机场景复验。自动更新须实际签名清单、端点及回滚验收，不能用占位配置声称已实现。
