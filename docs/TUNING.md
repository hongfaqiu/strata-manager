# 本机调优使用指南

[English](TUNING.en.md) · [用户指南](USER_GUIDE.md) · [验收记录](VERIFICATION.md)

调优会在这台电脑上比较同一模型的有限参数候选。默认的 **一键提速** 不重启模型，约 10 分钟；需要比较重启参数和完整任务质量时，使用高级区域里的 **场景验收**。它提供按用途验证的测量报告；没有稳定收益时继续使用原配置。当前实现已进行隔离 HTTP、真实后台子进程和浏览器合同验证，真实 GPU 与最终安装包中的完整调优仍待验收。

## 一键提速（默认）

打开 **参数调优** 后直接点击 **一键提速**，不需要先选用途。默认按「通用」测量：同时测短回答和 512 Token 以上的长回答，两者都不变慢才采用新设置。全程约 10 分钟，不重启模型、不改配置文件；测量期间模型暂时忙碌。

1. **体检**：打开页面即检查，不占用模型。
   - **显存余量**：引擎加载后空余显存低于安全线（Windows 1 GiB、其它系统 512 MiB；目标为「省显存」时 2 GiB）时，修复会预留显存（`--vram-reserve-mib`），并在专家缓存被写死时改为 `--expert-cache auto`。若引擎日志给出了建议值，按建议值取较大者。
   - **长上下文**：上下文 ≥ 64K、未设置常驻窗口、非 WSL 且空闲内存足够时，建议 `--kv-resident 32768`，把常驻窗口外的 KV 放到内存（约 13.7 KB / Token）。
   - **显卡与内存分工**：配置里写死 `--pcie-frac` 时提示会关闭引擎的自动调整，只作说明。
   - 修复会另存新配置版本（`*-speedfix-日期.json`）并切换过去，原配置文件不变。
2. **基线**：先用当前设置测速，结果始终显示为「调优前」。
3. **扫参**：复用快速校准逐项测量预填充分块、显卡与内存分工（PCIe）与 MTP 阈值。符合引擎自动条件时（CUDA ≥ 0.1.42 单卡或 RDNA4 ≥ 0.1.43，无分层、无 `--batch`、无 `--peer-device`），把「交给引擎自动」作为参照；固定值只有明显更快（超过 3%）才会写入，自动不慢（差距在 1% 以内）时会删除写死的 `--pcie-frac`。
4. **结果**：显示调优前后 tok/s、短回答与长回答各自的变化，以及每项改动的白话解释。找不到明显更快的设置时直接说明原因，不提供应用。
5. **采用** 会另存新配置版本（`*-speedup-日期.json`）并切换过去；**回滚到调优前** 会切回原来的版本，原配置文件始终未被改动。

**高级 · 专家模式** 默认折叠，可选：主要用途（通用／聊天／编程与 Agent／长文）、目标（速度优先／均衡／省显存）、每个值测几轮；详细测量图表与日志、另存或覆盖当前配置，以及下方的场景验收。历史短请求诊断报告仍可在此查看，但不再提供新的短请求诊断。

## 场景验收（高级）

### 怎样开始

1. 在桌面应用中等待本机模型就绪。已有模型可以导入，调优不会下载另一份模型。
2. 打开 **参数调优**，展开 **高级 · 专家模式**，在场景验收中选择 **日常聊天**、**编程与 Agent** 或 **长文分析**。
3. 通常保持默认设置，点击 **开始实测**。后台先等待空闲并进入维护；这段时间其它 API 请求会等待或收到忙碌提示。
4. 查看任务质量、重复收益、资源余量和恢复状态。只有通过全部条件的完整报告才可 **应用并验证**；测量本身会恢复原配置。
5. 应用后需要撤销时，选择 **恢复原参数**。报告可以导出，保留测量信息，不包含提示词、回答或工具正文。

调优期间不要在其它程序中编辑同一配置。检测到外部编辑时，应用会保留这些改动并报告需要修复，不会用旧报告覆盖新配置。

## 三种用途测什么

| 用途 | 实际任务 | 质量条件 |
| --- | --- | --- |
| 日常聊天 | 中英多轮聊天、冷输入、热前缀、会话切换、持续生成 | 事实及后续转换正确，结构完整，无截断 |
| 编程与 Agent | 读取固定代码夹具、生成补丁、运行受限确定性检查、工具结果续答；另测会话切换 | 工具参数及调用 ID 正确，补丁通过检查，最终结果完整 |
| 长文分析 | 实际 Token 计数后的多位置检索、长文前缀复用与会话切换 | 跨位置事实、关联与引用正确，输入和回答不超当前容量 |

编程测试使用固定的内存夹具与受限解释器，不执行模型生成的任意命令，也不修改用户项目。它证明该代表性任务通过，不代表整个项目或所有 Agent 都通过。

长文输入按当前容量和回答余量选择 16K、32K、64K 等可容纳档位。本次上下文上限只限制测试，不改变模型的 Context、KV 或 RoPE。默认长文测试上限为 32K，实际文档档位仍要为回答留出空间；更长档位可在高级设置中选择，容量不足会拒绝开始。

**同时检查图像理解** 只使用当前已配置的视觉能力与固定图像夹具，不下载视觉模型。未选择或未配置视觉时，报告不能将视觉显示为通过。未测的用途也不能推导为通过。

## 参数与推荐条件

默认比较当前值附近的 PCIe 预算与 MTP 阈值。高级设置最多添加四组独立重启候选：CPU 工作线程、异步换入、预填充分块、显存预留。后台不降低现有显存预留，也不自动开启大内存驻留模式。

启动参数会区分请求值与观测值：工作线程及异步换入需要有效遥测；预填充可能动态缩小，核验启动上限不等于证明每次实际分块；显存预留请求不等于测得可用显存。缺少有效状态时不会当作已生效。

每个候选执行交错的 **原参数 A → 候选 B → 原参数 A**，默认重复两轮。输出必须完整且通过语义检查，收益必须超过实测基线漂移并能重复。普通任务以各次生成请求耗时之和比较，Agent 使用包含受限工具处理的总耗时。报告中的任务总耗时还包含 Token 计数校准等开销，两种口径分别说明。

资源判断使用测量期间整机 RAM 和主 GPU 总占用采样，包含其它程序，不能当作模型独占成本。未知资源或不足余量的候选不推荐、不允许应用。当前保守余量门槛为 RAM 1 GiB、主 GPU 显存 256 MiB；这些抽样门槛不保证避免瞬时 OOM，也不代表更长上下文稳定性已验收。

短请求诊断已从界面移除；历史报告仍在高级区域中可查看。旧报告和短诊断不能新应用推荐参数，已应用报告的原参数仍可恢复。

## 取消、失败与恢复

界面显示实际阶段、已完成任务数和已用时间。完整测量硬期限为 2 小时；单个长文任务最多 20 分钟，其余任务最多 10 分钟。它们是停止期限，不是预计完成时间或提速承诺。

取消、加载失败、超时或 OOM 后，后台通过单独的恢复流程还原原配置字节，再检查原服务健康和短请求；恢复另有 7 分钟期限。取消只断开本任务的流，不调用服务全局取消。

若界面显示 **恢复失败**，先查看具体错误和配置恢复／服务核验两个状态。不要将它当作恢复成功或直接应用其它报告。后台保留恢复记录；若配置被外部编辑、实例归属不明或资源不足，需要解决提示的问题再准备模型。应用不会启动第二个大模型来绕过冲突。

模型、引擎、硬件或配置改变后，旧测量不再作为新应用的依据。当前报告中的驱动版本未知，模型文件以大小和修改时间绑定，资源为抽样结果；这些边界和真实 GPU、安装包验收进展见 [验收记录](VERIFICATION.md)。
