# 当前原型的生产化 UX 审查

日期：2026-10-10。范围：首次使用 → 已有安装入口 → 服务表单 → API空状态。通过Codex in-app browser现场操作，逐步保存并检查截图。没有提交表单或启停/更新真实模型。浏览器文件/环境功能禁用，不能以此评价原生安装能力。截图为本机忽略的产物；前3步1633×1244，末步恢复预览后1280×720，不用于跨尺寸像素对照。

## 1. 首次打开：需要重组

![首次打开](../output/product-audit-20261010/01-first-launch.jpg)

两条路径清晰，侧栏可识别；但检测安装前就出现11个导航项、“当前服务”选择器，并要求设置参数/启用服务。用户先要理解服务概念，页面留白较多。改为自动检测、发现模型或推荐安装，主操作为“开始使用”。

## 2. 已有安装：导入闭环不足

![已有安装](../output/product-audit-20261010/02-existing-install.jpg)

发现按钮和检测范围说明清楚，但只探测少数端口，仍要求手填其它端口/远程地址、后续点击加载。改为识别目录/配置/模型并确认导入；无法识别时只选择目录，之后自动完成可用性检查。

## 3. 服务表单：操作负担高

![服务表单](../output/product-audit-20261010/03-service-form.jpg)

同时要求名称、URL、managed、安装/配置/Python路径及密钥，暴露实现细节，导入模型和HTTP连接概念混杂。可见焦点清晰；前端模式浏览按钮禁用，真实文件选择未检查。改为自动登记环境，目录/配置仅在高级诊断或识别失败时出现。

## 4. API空状态：状态冲突

![API空状态](../output/product-audit-20261010/04-api-empty.jpg)

“尚未配置服务”与连接错误、模型“连接中”、空指标同时出现，API标题重复；用户尚未安装就会误以为软件故障。改为单一安装/导入入口；有真实历史后显示用量、速度及失败，细节放明细标签。搜索、过滤、计时与正文能力保留。

## 边界

共享布局与自绘控件可复用，底部收起入口已存在。小灰字、状态色和小图标仍需对比度/DPI、键盘及读屏专项检查，不能仅据截图判无障碍合规。本次未安装模型、GPU推理或验系统窗口/睡眠/更新。架构和验收见 [生产化方案](PRODUCTION_REDESIGN.md)。
