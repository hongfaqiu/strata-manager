# Strata Manager 使用指南

[官网](https://hongfaqiu.github.io/strata-manager/?lang=zh) · [返回产品介绍](../README.zh-CN.md) · [文档目录](README.md) · [English](USER_GUIDE.en.md)

[下载与体验](DOWNLOAD.md) · [故障排查](TROUBLESHOOTING.md) · [支持范围](DOWNLOAD.md#支持范围)

Strata Manager 是开源的本地模型管理桌面应用，把模型导入与准备、配置管理、服务启动与加载、聊天、监控和本机 API 集中在一个工作台中。项目基于 Strata 运行时；可用模型、图像输入、思考、MCP 工具和 API 协议以已安装的运行时和具体模型为准。

从“模型 → 我的模型”开始，点击“使用”，等待“模型可用”后聊天或连接本机 API。应用管理在这台电脑上准备或导入的安装，已有权重保持原位；不管理远程节点。

## 第一次使用

### 已经有 Strata 或模型

1. 打开“模型”，检查“我的模型”。旧版 Manager 的有效模型档案与聊天记录会自动恢复。
2. 首次使用时查看检测结果，选中已有安装并导入。检测遗漏时选择 Strata 文件夹即可。
3. 点击“使用”，等待模型可用，再进入聊天。原有模型保持原位，原配置保留，应用使用受管副本。

可导入的已有 Strata 模型不需要再次下载权重。检测到由其它程序运行的实例时，应用先核验来源与活动状态；身份不明或正在处理请求的进程不会被强制停止。如果无法接管，查看提示和日志后再处理。

### 还没有安装

1. 使用准备向导，应用下载并校验固定版本的官方源码，创建私有运行环境。
2. 从准备目录中选择模型，并选择其可用的量化、上下文和图像选项。目录以应用核验过的运行时为准，不是任意模型或任意 GGUF 文件的通用安装器。
3. 在任务中查看下载与准备进度。命令成功且资产核验通过后，模型自动加入列表；多份配置有歧义时按提示选择。
4. 点击“使用”。应用检查环境、启动服务并加载模型。

准备新模型不会自动替换当前选择。失败可以重试，也可以取消；权重较大时首次准备会需要较长时间。

模型卡片会显示实际数据目录、各目标磁盘的可用空间和预计新增量，并扣除可复用的权重或断点文件。开始准备前后台会再次检查；空间不足或无法确认时不会启动下载。数字是按所选模型及已核对的安装器规则估算，不能保证驱动、内存或全部依赖都已就绪。导入已有模型不需要再次准备或满足整套权重的下载空间。

Windows 检测 64 位 Python 3.10+；未找到时提供经 SHA256 校验的官方 Python 私有安装路径。Linux 需要 Python 3.10+、venv 和 ensurepip；缺失依赖会给出提示，应用不执行 sudo。Linux 崩溃保护还需要允许 pidfd、clone 和 close_range 的 64 位 Linux 5.9+ 环境；不支持时拒绝启动受管子进程。缺 Python 的完整安装分支仍待干净机器验收。

## 日常使用

| 页面 | 可以做什么 |
| --- | --- |
| 总览 | 查看模型可用性、后台状态、用量、资源和下一步操作 |
| 模型 | 检测导入、准备模型、查看任务、选择当前使用的模型 |
| 聊天 | 管理多个会话、流式回答、Markdown 与文本附件；图片、思考和 MCP 事件需模型与运行时支持 |
| 调优 | 比较受支持的 PCIe 预算与 MTP 推测参数，查看结果，再决定是否应用或恢复 |
| 监控 | API 用量、官方性能监控、按需请求正文诊断和日志 |
| 设置 | 语言、主题、后台策略、登录自启动、更新与运行配置 |

关闭窗口后，独立后台继续提供已经启动的 API。关闭窗口、退出界面和停止服务是不同操作；需要释放模型并结束受管服务时，使用托盘“停止服务并退出”。重新打开应用会连接同一用户已有的后台。

默认后台轻量运行，模型按需加载；可以选择启动时提前准备模型。登录自启动启动后台，不先打开聊天窗口。“自动恢复”针对所选受管服务退出后执行最多 3 次恢复尝试，连续失败会显示需要修复的状态，不保证自动解决所有 API 异常或卡死。

当前平台与实际使用限制见[支持范围](DOWNLOAD.md#支持范围)。Linux 崩溃保护要求满足前述运行环境，覆盖保留在受管进程组内的子进程；不能外推为所有另建会话的 MCP 工具都会被清理。

### 聊天、附件与运行配置

在聊天页新建或切换会话，通过附件按钮或拖放添加受支持文件。文本附件每个最多 512 KiB；图像需要服务报告图像支持。思考展示由模型返回内容决定，MCP 还需要已配置、可连接且有可用工具的服务器，打开选项本身不会增加工具能力。

聊天采样选项影响受支持的请求参数。“设置 → 运行配置”中的文件配置保存后需要主动重启受管服务，才能应用到运行时；查看页面提示，不把保存成功当作正在运行的配置已经改变。使用停止回答按钮可取消自己的生成，已收到的部分内容可能留在会话中。

## 阅读后台健康状态

总览的“后台健康检查”针对当前运行中的受管服务。进程存活、API 健康和模型已加载分别判断。

| 状态 | 如何处理 |
| --- | --- |
| API 健康 | 同时检查模型加载状态，再开始聊天 |
| 正在核验 API 异常 | 等待新的检查结果；持续异常时查看诊断 |
| API 连续异常 | 当前进程会保留；查看诊断后决定重试或停止 |
| 忙碌或维护中，延后检查 | 等待请求、加载或维护结束 |
| 尚未核验完整状态或等待新检查 | 按未知处理，不直接判断为健康或故障 |

巡检在核验到工作或维护时延后，连续空闲异常会显示诊断；巡检本身不会强行停止或重启进程。服务退出后的有界自动恢复是独立策略。

## 接入本机 API

先确认模型可用，再查看总览或模型页显示的本机服务地址。把客户端所需的 Base URL/API 路径配置为对应地址，不需要创建远程服务档案。

按客户端与当前运行时共同支持的协议配置路径：

| 客户端协议 | 常见 API 路径 |
| --- | --- |
| OpenAI Chat Completions | `/v1/chat/completions` |
| OpenAI Responses | `/v1/responses` |
| Anthropic Messages | `/v1/messages` |

客户端要求 OpenAI Base URL 时，通常使用对应的 `/v1` 地址，而不是聊天页面的网址；遵循客户端约定，避免重复添加路径。配置了 API Key 时，客户端也要使用同一密钥。某些客户端自身不能访问本机服务，应用不会绕过它们的网络限制。

首次加载大型模型可能需要较长时间，客户端超时要匹配实际加载时间。连接失败时依次检查模型状态、显示的端口、API 路径、密钥和日志。

## 阅读 API 用量

在“监控 → API 用量”选择今日、最近 24 小时或最近 7 天，可以查看请求趋势、成功率、失败/取消/中断、输入输出 tokens、缓存、首个输出等待时间、总耗时、解码速度、MCP 调用和最近请求。

今日按本机时区计算。元数据保留 90 天，后台持续采集；关闭监控页面不会停止采集。

HTTP 请求、模型推理轮次和工具调用分别计数。一次 MCP 请求可能有多轮推理，token-count 请求只计 HTTP 请求；HTTP usage 与推理工作量不能相加当作总 token 用量。成功率排除未结束请求。

缺失值显示未知，不等于零。请同时检查采集状态、兼容性与断档；开始采集前的时间不代表完整统计。客户端没有可识别标签时显示为未知来源。

请求历史支持自定义时间、来源、实际模型、完成状态及时间排序，并可翻页。翻页保持同一次查询的新记录边界；点击刷新才纳入后来收到的请求。正在执行的请求仍可能更新完成状态。早期未记录实际模型的请求显示未知，不能根据当前模型补写。

导出 CSV 会打开系统保存对话框，仅导出当前时间和筛选条件下的元数据。单次最多 5,000 条，超过时需要缩小时间或筛选范围；取消保存不会生成文件。CSV 不包含提示词、回答、思考、工具参数或密钥。

## 数据与隐私

聊天历史保存在本机。API 使用统计只保存请求与推理元数据，不保存提示词、回答、思考、附件、工具参数或 API 密钥。

官方 API Monitor 的请求正文捕获是独立诊断功能；导入的原配置可能已开启它。按需检查该设置，元数据统计不要求开启正文捕获。

模型推理在本机，运行环境、模型与更新下载需要网络。MCP 工具按用户配置执行，可能访问外部服务；请根据自己的工具配置判断其行为。报告问题或分享诊断前，移除密钥、私人路径和聊天内容。

## 参数调优

当前比较仅覆盖受支持的 PCIe 预算（pcie_frac）与 MTP 推测阈值（spec_min_p）。选择短对话、代码生成或中文长回答场景后，应用按“当前配置 A → 候选 B → 恢复 A”测量有限候选，区分新提示和立即重复前缀的表现。报告包含耗时、首个输出等待时间、速度、缓存与输出一致性。比较期间模型被占用，其他请求可能等待或提示忙碌，建议先结束聊天和外部客户端工作。

推荐要求收益超过当轮基线波动，并且确定性测试输出完整一致；结果不稳定时保留原配置。代码场景还检查 `merge_sorted(a,b)` 在空列表、重复值、负数、长度差异及固定随机输入上的正确性和输入保留。检查只支持这个题目的有限 Python 语法，不执行模型生成的 Python；不支持的写法会拒绝推荐。旧代码报告可查看和恢复已应用参数，重新应用需重新测量。上述检查不替代完整 Agent、一般代码质量、视觉、长上下文或冷加载测试。当前自动调优针对有限请求级参数；上下文、KV 和启动配置仍需结合容量及质量检查。

采用结果会保存恢复记录、重启受管服务并检查加载；失败时尝试恢复原配置。恢复本身也可能失败，此时保留诊断，需要修复后重试。应用期间本机 API 会短暂受影响，请避免并行维护。实际 GPU 收益以模型、硬件和测试报告为准，截图中的示例数值不代表性能结果。

## 应用更新

设置中的“自动检查并下载更新”会在打开应用时及每 12 小时检查新版本，下载完成后由你选择安装时间。也可以关闭自动下载，手动检查和下载；失败时保留当前版本并提供重试。下载不会提前停止本机 API，点击安装时才检查后台是否能够安全更新。正式更新使用内置公钥验证 Tauri 签名；应用、Strata 运行环境和模型权重分别管理，应用更新不会以重新下载模型作为正常流程。

v0.1.0-beta.1 预览版已发布，可手工下载 [Windows 安装包](https://github.com/hongfaqiu/strata-manager/releases/download/v0.1.0-beta.1/Strata.Manager_0.1.0-beta.1_x64-setup.exe)、[AppImage](https://github.com/hongfaqiu/strata-manager/releases/download/v0.1.0-beta.1/Strata.Manager_0.1.0-beta.1_amd64.AppImage) 或 [DEB](https://github.com/hongfaqiu/strata-manager/releases/download/v0.1.0-beta.1/Strata.Manager_0.1.0-beta.1_amd64.deb)，并核对 [SHA256SUMS](https://github.com/hongfaqiu/strata-manager/releases/download/v0.1.0-beta.1/SHA256SUMS)。预览版不替换稳定版 `latest` 更新通道；设置中的更新检查面向稳定更新来源，未检测到 beta 不代表当前预览版已经最新。

版本、安装包和当前支持范围见[下载与体验](DOWNLOAD.md)。Tauri 更新签名与 Windows 发布者代码签名不同，本项目目前没有 Windows Authenticode 发布者证书；请按下载说明处理系统的安装提示。

## 更新 Strata 运行环境

在“模型 → 详情与管理”选择“检查并更新 Strata”，确认后到任务页查看实际进度。后台在新目录准备应用核验过的固定版本、私有 Python 和引擎，继续复用已有权重与 tokenizer；原安装和配置保留。准备期间当前服务保持运行，切换时等待正在执行的请求结束并短暂关闭新请求准入。候选 API、加载和短请求检查失败或取消后尝试恢复旧登记与原加载状态。恢复也可能失败，任务会保留诊断，需处理原因后重新准备或恢复。

当前候选固定为 Strata 0.1.41，不承诺直接跟随上游最新版本。已核对的引擎包为 Windows x64；该上游版本没有匹配的 Linux 引擎发布包时会说明原因并保留现有安装。依赖外部启动命令或无法确认语义的配置会在停服务前拒绝迁移，需要先按诊断处理。完整候选依赖下载与真实 GPU 更新仍未完成验收，不把源码、引擎文件校验或夹具成功当作整个更新流程已通过。

## 遇到问题

| 现象 | 建议 |
| --- | --- |
| 找不到已有安装 | 选择 Strata 文件夹，检查源码、Python、配置及模型文件的诊断 |
| API 启动了，模型还不能聊天 | 等待模型加载，查看任务和日志；API 在线与模型可用是两个阶段 |
| 客户端连接失败 | 检查本机地址、路径、模型状态、超时与密钥 |
| 统计为空或未知 | 查看采集状态、兼容性和断档；旧版或改动过的运行时可能不支持完整观测 |
| 调优没有提速 | 保留原配置，用实际工作负载复验，不把缓存命中等同完整任务提速 |

详细步骤见[故障排查与反馈](TROUBLESHOOTING.md)。提交问题时说明系统、应用版本、操作步骤和脱敏后的错误信息。
